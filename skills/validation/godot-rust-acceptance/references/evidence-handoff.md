# Evidence and handoff

Record exact commands, tested snapshot, assertions, native and recorder status, inspected captures, review findings and remaining gaps in the existing runbook or ticket. Correct a wrong source runbook instead of leaving the fix only in chat. An isolated kernel or smoke test does not complete its World, CLI or UI integration milestone.

Generate paths, hashes and status fields from persisted receipts where practical. Hand-transcribing long digests and case-sensitive temporary paths has caused false review targets. Read the exact local parser diagnostic before preparing a negative assertion instead of paraphrasing it.

Keep concise conclusions linked to the complete report. Preserve failed earlier runs and disclose later checkpoint changes rather than claiming current files still match an older receipt. A post-run reviewer failure is not permission to edit native evidence or rerun a game merely to repair an inspector.

When an approval gap or ownership transfer occurs, record the source revision before and after it. State which reservations were released, what was revalidated and whether any dependent run remains unexecuted. Approval or a clean mechanical receipt is not itself functional acceptance.
