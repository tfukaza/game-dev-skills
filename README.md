# Game Dev Skills

Agent skills for building game environments with Blender and Three.js —
written while building [Dust II / Bombsite A](https://github.com/tfukaza/astra-dust-2),
a from-scratch reconstruction of a Counter-Strike map rendered live in the
browser.

## Skills

- **blender-threejs-environments** — Coordinate substantial game-environment
  creation or reconstruction using Blender and Three.js, from reference
  topology through asset delivery. Use for whole environments or changes
  spanning layout, art, and runtime; use the focused skills below directly
  for isolated edits.
- **blender-threejs-layout** — Build or revise playable Blender and Three.js
  environment layouts from maps, screenshots, annotations or a design brief.
  Topology, scale, terrain, architecture placement, connections and collision
  clearance.
- **blender-threejs-props** — Author reusable Blender and Three.js game props
  from references: modular models, image-generated surface lettering,
  coherent variants, foliage, support contacts and consistent detail levels.
- **blender-threejs-materials** — Author or revise Blender-to-Three.js PBR
  surface materials, including physical texture scale and stochastic tiling
  with coherent color, roughness and normals.
- **blender-threejs-surface-paint** — Author layered environmental wear, sand
  or dirt deposits, repairs, surface markings and lettering for Blender assets
  delivered through Three.js.
- **blender-threejs-baked-gi** — Bake calibrated diffuse lighting in Blender
  Cycles and deliver it to a Three.js scene: lightmap atlases, linear I/O,
  guarded denoising, compression and optional static-prop probes.
- **blender-threejs-asset-pipeline** — Export, package or update Blender
  assets for Three.js while preserving scene metadata, geometry, UVs,
  normals, tangents, material bindings and LOD contracts.
- **threejs-performance** — Diagnose and optimize interactive Three.js scenes
  with controlled CPU, GPU, loading, and memory measurements.
- **threejs-scene-qa** — Verify Three.js game scenes through reference
  comparisons, traversal, render-defect isolation, asset failures, and
  resource lifecycle checks.

Each skill directory contains its own `SKILL.md` plus supporting
`references/`, `scripts/`, and (where applicable) `fixtures/`.
